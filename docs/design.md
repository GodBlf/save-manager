# 首版设计

- 面向 Windows，使用 Rust 和 egui / eframe，管理本机的单机游戏存档。
- 支持多个游戏配置。每个游戏配置包含自己的追踪文件、追踪目录和独占的当前快照根目录，应用重启后保留配置。
- 用户点击「创建快照」时，应用复制该游戏的所有追踪路径。名称可选，示例为 `0/` 和 `0-A重要/`。
- 任意追踪路径复制失败时，整次创建失败。界面指出出错的路径，快照列表只展示完整保存的快照。
- 左侧显示游戏列表，右侧显示所选游戏的追踪路径、创建快照入口和快照历史。快照历史按创建时间倒序，显示编号、名称和创建时间。
- 游戏详情可打开快照根目录，每份快照可打开自己的目录。追踪目录直接打开，追踪文件打开所在目录并在资源管理器中选中该文件。用户可在资源管理器中查看和编辑存档内容。
- GUI 支持恢复存档、修改快照名称和删除快照。每个游戏从 `0` 独立编号。改名只输入名称，由应用保留原编号并生成目录名，例如 `0-A重要` 改为 `0-A次要`。
- 创建和改名使用相同的名称校验。名称支持中文和空格，去除首尾空白。留空时目录名仅为编号，遇到 Windows 不允许的名称时在界面提示。
- 已有游戏配置的快照编号在应用重启和切换根目录后延续，并跳过当前根目录内已占用的编号。创建失败时保留待用编号，创建成功后递增。删除快照后，编号不会重新分配。
- 删除快照前请求确认，确认后移到 Windows 回收站。如果目标位置不支持回收站，显示错误并保留快照。
- 切换快照根目录、重新选中游戏或点击「刷新」时，扫描当前快照根目录的直接子目录。快照历史只显示本次扫描识别到的快照。用户移出或删除快照目录后，刷新即可更新列表。
- 恢复前列出实际目标路径并请求确认。按创建快照时记录的路径恢复，整棵替换原存档目录，使恢复后的内容与快照一致。
- 恢复时先临时保留各目标的原有内容，全部成功后清理。中途失败时撤回已经完成的替换。撤回失败时保留临时副本，向用户显示副本路径。
- 用户可以用资源管理器复制快照，再在 GUI 中切换快照根目录。切换时扫描新根目录并识别其中的快照。应用只更新配置和列表，复制和清理由用户操作。
- 通过有效的 `.save-manager.json` 识别快照。普通的 `0/` 或 `1-通关/` 目录如果缺少有效的快照标识文件，就跳过该目录，同时保留其对编号的占用。
- 禁止同一游戏的追踪路径互相包含，也禁止追踪路径与快照根目录重叠。创建或恢复遇到符号链接或目录联接时，停止操作并显示相关路径。
- 恢复写入前记录进度和临时副本的位置。启动时发现恢复中断，提示用户确认后尝试撤回。处理完成前暂停该游戏的快照操作。
- 移除游戏配置前请求确认，保留磁盘上的快照。重新添加游戏时，扫描所选根目录以显示已有快照，新配置从该目录最大已占用编号的下一个编号开始。目录中没有已占用编号时，从 `0` 开始。
- 每份快照包含 `.save-manager.json`，记录唯一标识和原存档路径。用户复制快照时需保留此文件。追踪项原名与该文件冲突时提示用户。
- 游戏配置、下一个编号和未完成的操作记录保存在 Windows 应用数据目录。快照列表由当前根目录的扫描结果生成。
- 创建时先复制到临时目录，全部完成后发布。启动时清理未完成的临时目录。若快照已经完整发布但编号尚未更新，启动时根据操作记录接续编号，已发布的快照会随目录扫描出现在列表中。
