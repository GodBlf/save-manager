# Windows 单机游戏存档管理器首版规格

Status: ready-for-agent

## 问题陈述

单机游戏的一个存档状态可能分散在多个目录和文件中。玩家需要在关键进度前一次保存这些内容，之后能找到对应版本并将它恢复到游戏使用的位置。玩家也需要用资源管理器查看存档、手动编辑内容，以及在不同磁盘间整理备份。

## 解决方案

提供一个用 Rust 和 egui / eframe 实现的 Windows 本地 GUI。左侧是游戏列表，右侧显示所选游戏的追踪路径、创建快照入口和快照历史。用户可创建、打开、恢复、改名和删除快照。每份快照是可直接浏览的文件夹，用户可自行复制到其他目录，然后在 GUI 中切换快照根目录以查看复制后的历史。

## 实现决策

- 用 Rust 和 egui / eframe 实现 Windows 桌面应用。GUI 通过同一个 Rust 应用层接口发起配置和快照操作，并呈现结果、确认窗口和路径错误。
- 游戏配置保存追踪路径、当前快照根目录和下一个编号。游戏配置、编号进度及未完成的操作记录保存在 Windows 应用数据目录。当前快照根目录由对应游戏配置独占。
- 按游戏分别分配编号。已有配置在重启和切换根目录后延续编号并避开当前根目录内的占用。重新添加游戏时，以所选目录的最大已占用编号加一作为起点。没有占用时从 `0` 开始。编号在创建成功后递增，已用编号在删除快照后保留。
- 快照目录名由编号与可选名称组成。创建和改名共用 Windows 名称校验，去除名称首尾空白，空名称只保留编号。改名只修改名称部分。
- 快照顶层保留追踪项的原文件名或原目录名，目录内部按原结构复制。按 Windows 路径规则检查顶层名称冲突、快照标识文件的保留名称冲突、追踪路径之间的包含关系，以及追踪路径和快照根目录的重叠。创建和恢复遇到符号链接或目录联接时停止并报告路径。
- 每份快照用 `.save-manager.json` 标识，记录唯一标识及恢复所需的原存档路径。快照列表通过扫描当前根目录的直接子目录并验证标识文件生成，按创建时间倒序展示。缺少有效标识的目录仍占用其名称对应的编号。切换根目录只更新配置与扫描结果，用户在资源管理器中复制和整理快照。
- 创建先将完整内容写入临时目录，全部成功后发布。失败时报告路径，列表只展示已发布快照。重启时清理中断的临时副本，若目录已发布则根据操作记录接续编号，并由扫描将该快照显示在历史中。
- 恢复前展示创建时记录的所有实际目标，请用户确认。恢复完整替换目标目录。写入前记录操作进度和临时副本的位置，全部成功后清理副本。中途失败时撤回已完成的替换，撤回失败时保留副本并报告位置。重启发现中断时提示用户确认撤回，期间暂停该游戏的快照操作。
- 删除快照前请求确认，通过 Windows 回收站处理。回收站操作不可用时保留快照并报告错误。移除游戏配置也需确认，磁盘中的快照继续保留。
- 通过 Windows 资源管理器打开当前快照根目录、某份快照目录和追踪目录。打开追踪文件的位置时选中该文件。

## 测试决策

- 通过 GUI 调用的同一个 Rust 应用层接口验证配置、扫描、快照和恢复行为。测试使用临时目录和真实文件系统，断言操作结果、文件内容、目录树、路径错误和应用重启后的可见状态。
- 覆盖多游戏配置持久化、多个追踪项的原样保存、空名称和中文名称、改名保留编号、冲突校验、复制失败以及中断发布后的编号接续。
- 覆盖手动复制后切换根目录、刷新发现外部移出、重新添加游戏后扫描历史、普通目录占用编号和切换根目录后保留编号进度。
- 覆盖恢复时完整替换目录、配置变更后按旧路径恢复、中途失败撤回、撤回失败时保留副本以及重启后的中断提示和操作暂停。
- 在 Windows 上单独验证资源管理器打开和选中文件、回收站删除与不可用时保留快照。通过 GUI 验证主要操作入口、确认窗口的目标路径和界面刷新。
- 当前项目处于设计阶段，应用代码和既有测试尚未建立。

## 补充说明

- 手动搬运快照时，请在资源管理器中复制完整的快照子目录，包括 `.save-manager.json`。选中新根目录后，历史只显示该目录中的快照。
- 目录布局、恢复目标与当前根目录扫描分别有对应的设计决策。参考项目仅提供游戏列表到快照历史的操作流程作为借鉴。
